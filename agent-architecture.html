全模态 Agent 内核架构地图

这页把 Claude Code、Cursor、Codex、OpenClaw、OpenHands、Aider、SWE-agent、LangGraph、OpenAI Agents SDK、AutoGen、CrewAI、Semantic Kernel、LlamaIndex、AutoGPT、MetaGPT、BabyAGI、SuperAGI、Agency Swarm、Open Interpreter 等公开资料和源码抽象成一套可实现的模块分工。重点不是 UI，而是内部 runtime、上下文、工具、沙箱、记忆、长任务和多模态能力如何分层。

资料边界：Claude Code 与 Cursor 的核心产品源码不是公开源码；本页只使用官方文档、公开 SDK、公开仓库和可验证的源码结构，不使用或复现任何泄露、非授权代码。
18个公开 agent / framework / coding assistant 被归纳。
14个内核模块构成推荐架构。
3种主语言边界：TypeScript、Rust、Python。
0个 UI 依赖；页面只讨论 runtime 内部实现。

一、推荐模块包含关系

把 agent 当成一个操作系统内核：入口适配器只是 syscall，真正的核心是状态、上下文、工具执行、安全边界和可恢复任务。

运行时分层

Interface AdaptersCLI、HTTP、Webhook、MCP、文件/图片/音频/视频输入。
Intent Router + Context Engine判断任务类型，检索代码、文档、记忆和多模态上下文。
Planner + Agent Runtime计划、tool loop、handoff、subagents、checkpoint、interrupt/resume。
Tool Runtime + Sandbox文件、shell、git、browser、MCP、代码执行、权限策略。
Task Control Plane + Observability长任务、队列、定时任务、事件日志、trace、评测回放。

二、核心模块分工

下面是实现时应该拆出的最小稳定边界。每个模块都可以先做简单版本，但边界不要混在一起。

1. Input Adapters

把不同入口统一成 UserRequest / SessionEvent：CLI、API、Webhook、MCP、文件和多媒体附件。

CLIHTTPMCPattachments

2. Model Gateway

统一 OpenAI、Anthropic、Gemini、本地模型、embedding、vision、audio；负责 fallback、限流、成本和结构化输出。

routingfallbackcostschema

3. Context Engine

Agent 智商很大程度来自上下文。组合 code index、semantic retrieval、BM25、project rules、history 和 token budget。

tree-sitterLSPhybrid searchpacker

4. Planner

把目标拆成 milestone、task、action，并持续根据 observation 重规划。不要只做一次性 plan。

planactobservereplan

5. Agent Runtime

执行 tool loop、handoff、subagent、interrupt/resume、max turns、checkpoint；这是无 UI 内核的主循环。

ReActhandoffstate graphcheckpoint

6. Task Control Plane

管理 queued/running/blocked/succeeded/failed/cancelled，支持后台任务、定时任务、恢复、锁和 worker。

SQLite firstworkerscronresume

7. Tool Registry

工具定义和执行分离：注册 name、description、JSON Schema、权限等级、超时、side-effect level。

schemadispatcherMCPplugins

8. Built-in Tools

文件、搜索、patch、shell、git、浏览器、web fetch、数据库、多模态处理、外部 API。内置工具要少而强。

fileshellgitbrowser

9. Sandbox

隔离命令、代码、浏览器和网络。最小版本是 subprocess + timeout + workspace path guard；生产版本用 Docker/gVisor。

Dockertimeoutnetwork policyworkspace

10. Policy Engine

模型只能提出动作，runtime 决定是否允许。路径、网络、命令、凭证、预算和审批都应由 policy 控制。

approvalsecretsbudgetaudit

11. Memory System

拆成 working memory、episodic event log、semantic memory、project memory、procedural skills，避免全塞向量库。

event logfactsvectorskills

12. Multimodal Layer

图片走 vision/OCR，音频走 ASR/TTS，视频走 keyframes + ASR + OCR，PDF/Office 走 layout parser。

imageaudiovideodocuments

13. Plugin / Skill / Hook

插件扩展工具和 provider；skill 封装可复用 workflow；hook 在 tool/model 前后插入审计、格式化、测试和通知。

manifestpermissionshooksskills

14. Observability / Evals

每个模型调用、工具调用、上下文来源、policy 决策和文件变更都要可追踪，可用历史 trace 重放回归。

OpenTelemetrytracegolden tasksreplay

三、一次任务的内部数据流

这条链路综合了 Claude Code SDK 的 tool loop、Codex 的 JSONL 事件流、OpenHands 的 Action/Observation 和 LangGraph 的 checkpoint 思路。

1. Normalize
入口把用户文本、附件、仓库路径、权限上下文归一化为 RunRequest。
↓
2. Route + Retrieve
Intent Router 判断任务类型；Context Engine 拉取代码符号、相关文件、项目规则、历史记忆和媒体摘要。
↓
3. Plan
Planner 生成任务清单、风险等级、需要的工具和完成标准，写入 task ledger。
↓
4. Act
Agent Runtime 调模型，处理 tool calls；Tool Runtime 根据 schema 执行文件、shell、git、browser、MCP 或多模态工具。
↓
5. Guard + Observe
Policy Engine 审批或拒绝；Sandbox 执行；结果变成 Observation，写入 event log 和 checkpoint。
↓
6. Verify + Replan
运行测试/检查/视觉验证；失败则 replan，成功则输出 final response、diff、artifacts、trace。

四、主流项目模块对比

下面不是简单罗列功能，而是抽取每个项目最值得学习的内部边界。

项目 主要模块 编排范式 最值得吸收的设计
Claude Code Agent SDK、tools、MCP servers、hooks、subagents、sessions、background/scheduled tasks、project memory。 Tool loop + hooks + subprocess session。 PreToolUse/PostToolUse hooks、声明式 subagent、permission mode、session resume；只参考官方文档/SDK。
Cursor rules、agent tools、codebase indexing、semantic search、file edit、terminal、browser/checkpoints。 IDE 内 agent + index/context 驱动。 代码库索引和上下文选择是核心能力；重大修改前本地 checkpoint 独立于 Git。
OpenAI Codex Rust core、TypeScript SDK、Thread、ThreadEvent、ThreadItem、exec JSONL、sessions。 Rust 子进程 + JSONL event stream。 强类型 command_execution / file_change / mcp_tool_call / todo_list item，让运行过程可审计。
OpenClaw gateway、channel plugins、agents、tasks、tools、memory、extensions、config、security。 Gateway-and-agents hub/spoke。 把 channel 接入、agent 生命周期、插件加载、任务 ledger 和工具执行统一到 gateway。
Aider coders、repo map、models、git repo、linter、IO。 单 agent 多编辑策略。 RepoMap 用 tree-sitter/ctags 压缩代码库；编辑格式策略用 Coder 子类多态切换。
SWE-agent agent、models、action sampler、history processors、environment、tools、run configs。 Agent + Docker environment step loop。 history_processors 可插拔压缩；Docker 环境让代码执行副作用可控。
OpenHands controller、agenthub、runtime、events、memory、llm、mcp、security、resolver。 Action/Observation event stream。 所有行为都变成 Action/Observation，天然支持回放、调试、运行时替换和 stuck 检测。
LangGraph graph、pregel、channels、checkpoint、stream、func、prebuilt。 有状态图 + Pregel loop。 checkpoint、interrupt、Command、Send 是长任务和人在回路的基础原语。
OpenAI Agents SDK Agent、Runner、Tool、Handoff、Guardrail、Session、MCP、Tracing。 轻量 tool loop + handoff。 少量原语表达多 agent；Input/Output Guardrail 可以并行触发 tripwire。
AutoGen core runtime、RoutedAgent、Topic、Subscription、agentchat teams、tools、state。 Actor 消息总线 + group chat。 编排与 Agent 分离；pub/sub、RPC、intervention handler 支持大规模 agent 拓扑。
CrewAI Crew、Agent、Task、Process、Flow、Memory、Knowledge、Tools、A2A。 角色-任务团队 + Flow。 Agent 像团队成员，Task 是工作单元；4 类 memory 和 task checkpoint 值得借鉴。
Semantic Kernel Kernel、Plugin、Function、Agent、orchestration、filters、connectors、processes。 Kernel plugin pipeline + 多编排模式。 Filter 管道是生产级 AOP：函数调用、prompt 渲染、自动工具调用都能拦截。
LlamaIndex Agents Workflow、BaseWorkflowAgent、Function/ReAct/CodeAct Agent、AgentWorkflow、tools、memory。 事件驱动 workflow。 ctx.store 保存共享状态；ObjectRetriever 适合大量动态工具检索。
AutoGPT classic agents、prompt strategies、plugins；platform executor、blocks、data、api、integrations。 Classic ReAct；Platform DAG blocks。 新平台把 agent 建成节点图，Block SDK 适合可扩展自动化。
MetaGPT roles、actions、environment、memory、tools、provider、rag、team。 Team → Role → Action + pub/sub。 团队角色化和消息总线适合复杂协作；经验池可复用成功轨迹。
BabyAGI Functionz framework、executor、registrar、DB router、function packs、API。 函数注册 + 触发链。 最小可行的动态函数系统：函数可存储、版本化、触发其他函数。
SuperAGI agent loop、task queue、tool builder、tools、resource manager、vector store、Celery worker。 Workflow/Iteration 状态机。 WAITING_FOR_PERMISSION 状态把 human-in-the-loop 做成结构化流程。
Agency Swarm Agency、Agent、SendMessage、tools、MCP manager、file manager、streaming。 OpenAI Assistants + 有向通信图。 跨 Agent 消息就是一个 tool call；通信拓扑显式配置，避免任意互调。
Open Interpreter Rust runtime、TUI、sessions、harness、exec、MCP、skills、sandbox。 Harness 模板驱动的本地执行 agent。 多 harness 让不同模型复用同一 runtime；本地系统沙箱和 MCP 是关键。

五、实现语言建议

如果目标是 Claude Code/Cursor/Codex/OpenClaw 级别的无 UI 全模态内核，单语言可以 MVP，但长期最好拆清边界。

TypeScript-first

推荐作为第一阶段主栈：CLI/API、MCP、插件、JSON Schema、Playwright、WebSocket、配置系统都很顺。

  • 适合快速做 agent runtime、tool registry、browser automation。
  • 能和未来 UI、extension、MCP server/client 共用类型。
  • 缺点是高性能索引和进程隔离不是强项。

Rust native core

适合 CLI 单二进制、文件扫描、tree-sitter 索引、diff、进程 runner、sandbox policy。

  • 参考 Codex 和 Open Interpreter 的方向。
  • 可通过 JSONL/gRPC/WASM 暴露给 TypeScript runtime。
  • 缺点是前期开发速度慢，AI/多模态生态弱。

Python multimodal workers

适合 OCR、ASR、TTS、video keyframe、PDF layout、评测数据处理和实验性模型。

  • 不要让 Python 承担整个 runtime；更适合作为 worker 或 tool server。
  • 通过 MCP/HTTP/queue 接入主 runtime。
  • 可直接复用 LlamaIndex、LangGraph、OpenAI Agents SDK 做实验。
阶段 目标 必须模块 完成标准
MVP: coding agent 无 UI 本地仓库任务。 CLI、model gateway、agent loop、file/search/patch/shell/git、SQLite event log。 能修改代码、运行测试、修复失败、输出 diff 和 trace。
Context engine 接近 Cursor 的代码理解。 tree-sitter/LSP、repo map、hybrid retrieval、context packer、project memory。 能在大项目中定位相关文件，解释跨文件调用和依赖。
安全与扩展 从 demo 到可托管 runtime。 policy、approval、sandbox、MCP、plugin manifest、secret filter、audit。 高风险操作会被拦截或审批；工具可热插拔且可审计。
长任务与多 agent 类似 OpenClaw/Claude background agents。 task ledger、worker、scheduler、checkpoint/resume、subagent、workflow graph。 任务可中断恢复，研究/实现/验证可并行派发。
全模态 文本、代码、图像、音频、视频、文档统一处理。 OCR/vision、ASR/TTS、video timeline、PDF/doc parser、browser/computer use。 能从截图修 bug、从录音生成任务、从视频和文档提取可执行上下文。
